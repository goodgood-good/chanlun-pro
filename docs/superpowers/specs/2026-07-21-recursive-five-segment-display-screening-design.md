# 递归五段中枢、分级显示与提前选股修复设计

## 1. 状态、范围与最终决策

本规格记录 2026-07-21 已逐项确认的产品语义，采用方案 B：中枢、走势类型、买卖点、背驰、图表和提前选股共享同一套严格结构真值，不保留并行的旧算法真值。

本次工作同时覆盖三个相互依赖的交付面：

1. 将正式中枢改为“初始五个已锁定线段”口径，并明确进行中、延伸、第三类买卖点和完成态。
2. 重做图表“缠论显示设置”，按当前 K 线内部递归产生的结构级别展示中枢、走势类型和两类背驰。
3. 修复提前选股中 TDX 行业指数严格结构不可用导致板块和个股均为空的问题，并建立批次质量门。

本规格在以下冲突点上覆盖旧规格或现有实现：

- 覆盖 `2026-07-20-source-faithful-zhongshu-engine-design.md` 中“初始三个构件即建立正式中枢”的产品口径。新的正式中枢必须通过本文定义的五段门槛；中间第 2～4 段仍负责确定核心区。
- 覆盖现有 `FREQ_CHAIN` 对周线、月线的扩展。本文所涉递归显示最高只到日线标签。
- 禁止用独立加载的原生 5m、30m、日线 K 线结果冒充当前图表 K 线递归产生的高级别结构。
- 背驰不再只作为买卖点的附属字段；严格快照必须提供按递归级别分组的独立背驰证据。
- QMT 股票行情继续遵守既有严格价格基准契约；本文只为已明确识别的 TDX 880 行业指数增加独立的无复权价格基准边界，不放宽其他数据源的 fail-closed 规则。

## 2. 已验证现状与根因

### 2.1 图表显示缺口

当前 `charts.js` 只有基础结构、部分中枢、逐级走势、确认/接近点等零散开关；缺少中枢总开关、走势类型总开关和独立的分级背驰开关。现有递归级别菜单还会随 `FREQ_CHAIN` 在 5m、30m 图上出现周线或月线标签，与本次确认的映射不一致。

严格图表快照当前按 `levels` 输出中枢、当前走势、完成走势和买卖点，但没有可独立渲染的 `divergences` 集合。盘整背驰和趋势背驰只能从点位内部间接推断，因而无法可靠地按级别、按类型控制显示。

### 2.2 中枢语义缺口

当前未提交的严格状态机以三个锁定构件的交集立即建立中枢，无法表达以下已确认规则：

- 第 1 段是进入段，第 5 段是离开段；二者都必须与核心区有正宽重叠。
- 只有中间第 2、3、4 段决定固定核心 `[ZD, ZG]`。
- 第 5 段既要与核心重叠，又必须沿其方向把终点带到核心之外。
- 初始五段成立后，中枢处于进行中；完整回抽不重新进入核心时，第三类买卖点与中枢完成必须原子产生。

### 2.3 提前选股空结果的运行时根因

本地 `9900` 页面和落盘快照显示：81 个行业板块均被标记为 `sector_structure_unavailable`，最终选中板块数为 0，股票信号扫描为 0/0；快照本身却被发布为 `complete`。

调用链的具体失败点如下：

1. 生产板块源使用 `ExchangeTDX` 获取 880 行业指数 K 线。
2. 这些 `DataFrame` 没有 `structure_price_quantum` 与 `price_basis_revision` 属性。
3. `analyze_native_frame()` 已切换到严格分析入口，因而抛出 `ValueError: structure_price_quantum metadata is required`。
4. `NativeTradingDataGateway.native_sector_assessments()` 捕获宽泛异常后，将所有真实原因压平成 `sector_structure_unavailable`。
5. 排名器没有任何可选板块，后续成员股票扫描自然不会启动。

现有测试没有暴露该问题，是因为测试夹具主动为板块帧补上了两个严格元数据字段，和真实 `ExchangeTDX` 返回值不一致。

## 3. 概念边界与递归级别映射

### 3.1 时钟周期与结构级别

“1m 中枢、5m 中枢、30m 中枢、日线中枢”是当前页面上的结构级别标签。其数据源始终是当前图表所加载的 K 线，再由严格引擎逐级递归；这些标签不表示重新请求对应原生周期行情。

例如，在 1m K 线图上：

```text
1m K 线 -> L0 线段中枢（显示为 1m）
         -> L0 已完成/锁定走势递归 -> L1 中枢（显示为 5m）
         -> L1 已完成/锁定走势递归 -> L2 中枢（显示为 30m）
         -> L2 已完成/锁定走势递归 -> L3 中枢（显示为 日线）
```

页面允许的固定映射为：

| 当前 K 线 | 可展示的内部递归级别 |
| --- | --- |
| 1m | L0=1m、L1=5m、L2=30m、L3=日线 |
| 5m | L0=5m、L1=30m、L2=日线 |
| 30m | L0=30m、L1=日线 |
| 日线 | L0=日线 |

周线、月线不在本轮递归显示映射中。若当前基础 K 线不足以递归到某一级，快照返回该级为空或带明确证据不足诊断，不能用原生高周期结果补位。

### 3.2 正式结构与观察结构

- `分型 / 笔 / 线段` 是基础结构。
- `笔中枢` 是观察层，可显示，但不参与正式走势递归、买卖点、选股、回测或交易。
- 正式 L0 中枢从已锁定线段构成；L1 及以上中枢只消费下一低级别已经完成并锁定的走势类型。
- 进行中的中枢和走势可以展示，也可作为提前观察证据；只有满足锁定规则的低级别走势才能成为更高级别递归输入。

## 4. 五段中枢模型

### 4.1 初始五段几何规则

候选初始序列为五个连续、方向严格交替且均已锁定的线段 `U1..U5`。每段的闭区间记为 `[low_i, high_i]`。

角色固定为：

- `U1`：进入段；
- `U2、U3、U4`：核心三段；
- `U5`：离开段。

核心只由中间三段确定：

```text
ZD = max(low_2, low_3, low_4)
ZG = min(high_2, high_3, high_4)
```

必须同时满足：

1. `ZD < ZG`，即核心具有正宽度；仅在边界相触不成枢。
2. `U1` 与 `[ZD, ZG]` 的交集具有正宽度。
3. `U5` 与 `[ZD, ZG]` 的交集具有正宽度。
4. 若 `U5` 向上，其终点必须满足 `end_5 > ZG`；若 `U5` 向下，其终点必须满足 `end_5 < ZD`。

任一条件不满足，都只能产生稳定诊断，不能建立正式中枢。初始五段全部锁定且条件全部满足时，创建状态为 `ONGOING` 的正式中枢。

### 4.2 不可变身份与可变修订

`TrendCenter` 显式保存进入段、核心三段、初始离开段和后续离开/回抽事件，不再让消费者根据起止时间猜角色。

以下字段在中枢创建后不可变：

- `center_id`；
- `structural_level`；
- `price_basis_revision`；
- 初始 `U1..U5` 的身份；
- `ZD / ZG`。

`center_id` 由价格基准、结构级别和初始五段身份生成。后续延伸只递增 `body_revision` 并追加事件，不改变核心或身份。完成时追加 `completed_at`、完成见证和第三类点引用，不重写历史几何。

### 4.3 进行中、延伸与完成

初始 `U5` 已完成有效离开后，中枢等待相反方向的完整回抽：

- 回抽与核心有正宽重叠：视为重新进入，中枢继续 `ONGOING`，核心不移动；后续新的完整离开/回抽按同一规则继续评估。
- 向上离开后的完整向下回抽满足 `return_low >= ZG`：没有重新进入核心，确认第三类买点。
- 向下离开后的完整向上回抽满足 `return_high <= ZD`：没有重新进入核心，确认第三类卖点。

边界相触没有正宽重叠，属于“不重新进入”。第三类点、中枢 `COMPLETED` 状态和 `completed_at` 必须在同一次状态转移中原子产生，任何消费者都不能看到“已有三买/三卖但中枢仍进行中”或“中枢已完成但没有完成见证”的中间状态。

仍在核心内摆动、尚未形成合格离开、或者回抽尚未锁定时，中枢保持进行中，不得提前产生第三类点。

### 4.4 扫描与稳定性约束

- 少于五段不成正式中枢。
- 输入必须连续、方向交替、全部锁定且属于同一价格基准和结构级别。
- 批量计算和逐前缀增量计算必须得到相同的 `center_id`、核心、状态、确认时间和事件序列。
- 新 K 线只能追加或完成右侧活动结构，不能改变已经锁定前缀中的中枢身份和核心。
- 上下方向规则必须镜像对称。

## 5. 走势类型、买卖点与背驰

### 5.1 走势类型

每个允许的递归级别独立输出盘整、上涨趋势或下跌趋势，并携带 `ONGOING / COMPLETED / LOCKED` 状态。当前活动走势可以显示；只有 `LOCKED` 的低级别走势进入上一层五段中枢状态机。

走势类型必须引用其构件和中枢身份，不允许前端根据矩形数量重新推断。级别标签使用第 3.1 节映射，数据来源仍是当前图表 K 线的递归结果。

### 5.2 买卖点

严格快照继续输出六种正式点：一买、二买、三买、一卖、二卖、三卖，并为每个点携带结构级别、确认时间、证据引用和稳定身份。

图表只绘制已确认的正式点。`approaching` 继续服务提前选股和观察链路，但不作为正式图表买卖点，也不放入六种正式点开关。三买/三卖必须遵守第 4.3 节的中枢完成原子性。

### 5.3 独立背驰证据

每个递归级别新增独立 `divergences` 集合，不再要求背驰一定附着于某个买卖点。每条证据至少包含：

- 稳定 `divergence_id`；
- `structural_level`；
- `kind = consolidation | trend`；
- 方向；
- 比较构件与信号构件身份；
- 确认时间；
- 采用的力度度量和可审计比较结果；
- 关联点位身份（存在时），但该关联不是背驰成立的前提。

盘整背驰只比较同一盘整结构中可比的同向离开运动；趋势背驰只比较同一级别已形成趋势中的可比同向运动。两者不能互相改名或合并显示。未锁定比较构件只能进入提前观察证据，不能进入正式背驰集合。

## 6. 图表输出契约与渲染

严格图表快照继续以 `levels` 为结构边界。每级统一提供：

- `centers`：包含角色、核心、`ONGOING / COMPLETED` 状态和修订；
- `current_trends` 与 `completed_trend_snapshots`；
- `confirmed_points`；
- `divergences`；
- 仅供观察的 projection/approaching 扩展字段。

显示规则为：

- 进行中中枢使用虚线，完成中枢使用实线；核心 `[ZD, ZG]` 始终不随延伸移动。
- 进行中走势与完成走势使用可辨别的虚实样式。
- 投影随对应正式图层自动显示，不再暴露内部“投影”开关。
- 图形 reconciliation 以稳定身份和 revision 更新，不能用数组位置或临时时间范围辨认同一对象。
- 任一级证据不足时只不绘制该级，并显示稳定诊断；不能回退到旧中枢或原生高周期结果。

## 8. TDX 行业指数价格基准与选股链路修复

### 8.1 行情口径

TDX 880 行业指数使用数据提供方维护的原生连续指数序列，明确请求 `fq=none`。行业指数不存在股票式公司行动复权语义，不能对其使用或伪装 `qfq/hfq`。

在已明确识别为 TDX 880 行业指数的适配边界，为非空 K 线附加正式价格基准元数据：

- `provider = tdx-industry-index`；
- 规范化市场与指数代码；
- `adjustment = none`；
- 由 TDX 行业指数报价精度解析器确定的 `structure_price_quantum`；解析失败时 fail-closed，不能套用股票 tick 猜测；
- 由 schema、provider、市场、代码、adjustment 和 quantum 生成的稳定 `price_basis_revision`。

元数据在周期裁剪和 `_closed_frame` 复制后必须保持一致。只对明确分类成功的 880 行业指数应用此契约；其他 TDX 标的或 QMT 股票缺少元数据时仍按各自既有规则 fail-closed。

### 8.2 可观察错误而不是宽泛吞错

`native_sector_assessments()` 不再把所有异常无差别压平。每个板块分析结果必须区分：

- 分析成功但结构条件不合格：这是有效业务结果，计入已完成分析；
- 行情为空或过期；
- 价格基准元数据不可用；
- 严格结构计算失败；
- 未预期的适配器异常。

对外快照使用稳定错误码；服务端日志保留板块代码、周期、provider、adjustment、异常类型和原始消息。响应不暴露堆栈或 SDK 私有内容。

### 8.3 板块质量门与发布原子性

板块分析必须先完成质量判定，再排名选板块和规划股票扫描：

1. 记录发现板块数、分析成功数、基础设施失败数、成功率和分错误码计数。
2. “结构条件不合格”属于成功分析；只有无法得到可信结构结论的情况计为失败。
3. 复用现有 `min_scan_completion_ratio`，默认阈值 `0.80`，作为板块阶段成功率门槛。
4. 低于阈值时，本轮状态为 `incomplete_not_published`，不以全空结果覆盖上一份有效快照，不启动由本轮板块选择产生的股票扫描，并重新排队失败项。
5. 达到阈值后才对有效结果排名、选择板块、展开成员股票并进入现有股票扫描质量门。

合法的“没有合格板块”或“没有买卖点信号”允许为空，但必须建立在板块分析通过质量门之后，并提供逐项业务原因；系统不得为了验收伪造选中板块或股票。

完整链路为：

```text
ExchangeTDX 880 原生连续 K 线（fq=none）
  -> 附加并传播严格价格基准元数据
  -> 严格结构分析
  -> 板块分析质量门
  -> 有效板块排名与选择
  -> 成员股票扫描计划
  -> 股票严格结构与信号评估
  -> 原子发布新快照
```

## 9. 版本迁移与缓存失效

五段状态机、独立背驰和板块审计字段都会改变真值或输出形状，旧缓存不得混用。实施时统一升级：

- 严格证据身份：`chanlun-strict-evidence/v3`；
- 中枢图形协议：`chanlun-chart-center/v4`；
- 图表严格结构协议：`chanlun-chart-structure/v4`；
- 图表快照/渲染 revision 输入同步升到 v4；
- 图表缓存 schema：`v40`；
- 严格 CL 对象缓存 namespace：`strict-v3`；
- 提前选股快照：`chanlun-trading-screening/v2`；
- 提前选股 `structure_version = v2`；
- 前端显示配置对象增加 `schema_version = 2`，保留现有按 chart/resolution 的存储 key，并执行幂等迁移。

所有旧三段中枢、旧背驰附属字段和旧选股结构版本只能被视为缓存未命中；不能在新页面中兼容绘制后继续参与真值计算。

## 10. 实施边界

按以下可独立验证的单元推进，每个单元都先写失败测试、最小实现、完整通过后单独提交：

1. 五段中枢几何、进行中/完成状态机与身份修订。

5. TDX 880 无复权价格基准、属性传播、板块诊断与质量门。

## 12. 风险、控制与非目标

### 12.1 预期变化

五段正式门槛会改变中枢数量、确认时点、递归深度和买卖点数量；旧三段快照不能用于新旧结果混合比较。应通过固定夹具和真实前缀回放解释差异，而不是保留旧算法兜底。

递归级别标签容易被误读为原生时钟周期。UI 和 payload 必须保留结构级别身份，文案明确“由当前 K 线递归产生”。

行业指数采用原生连续、无复权序列后，provider 或精度规则改变必须生成新的 `price_basis_revision`，从而重建结构，禁止跨基准续算。

### 12.2 非目标

- 不新增周线、月线递归显示。
- 不把原生高周期行情与当前 K 线递归真值并排混入本菜单。
- 不改变行业指数供应商的指数编制方法，也不人为构造复权因子。
- 不放宽 QMT 股票或未知市场的严格价格元数据校验。
- 不把 approaching 信号升级为正式图表买卖点。
- 不让笔中枢进入正式递归、选股或交易。
- 不以“必须出现选中股票”为验收条件；只要求数据链可信、扫描确实发生、空结果可解释。
