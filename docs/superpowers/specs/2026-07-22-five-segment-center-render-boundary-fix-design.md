# 五段中枢本体横向边界修复设计

## 1. 状态与决策

本文补充并收紧 `2026-07-21-recursive-five-segment-display-screening-design.md` 的图表几何语义。用户已确认采用方案 A：五段正式中枢的初始矩形只覆盖核心三段 `U2～U4`；`U1` 是进入段、`U5` 是离开段，二者仅作为成立证据，不进入矩形横向本体。

本修复只改变中枢矩形和进行中投影的时间坐标，不改变五段成立条件、固定价格核心 `[ZD, ZG]`、递归级别、颜色、进行中/完成状态或第三类买卖点规则。

## 2. 运行时根因证据

`SH.513100 / 5m` 最新正式 L0 中枢的五段证据为：

| 角色 | 市场时间 | 区间（tick） |
| --- | --- | --- |
| U1 进入段 | 2026-06-22 10:35 ～ 2026-06-26 10:35 | 2133～2311 |
| U2 核心段 | 2026-06-26 10:35 ～ 2026-06-30 09:35 | 2133～2214 |
| U3 核心段 | 2026-06-30 09:35 ～ 2026-06-30 11:30 | 2200～2214 |
| U4 核心段 | 2026-06-30 11:30 ～ 2026-07-01 11:20 | 2200～2223 |
| U5 离开段 | 2026-07-01 11:20 ～ 2026-07-03 09:40 | 2144～2223 |

五段全部与固定核心 `[2200, 2214]` 有正宽重叠，价格核心与第三类卖点完成状态均正确。错误位于 `strict_center_to_chart_dict()`：它把矩形时间直接序列化为 `body_start_market_time ～ last_touch_market_time`，因此实际画成 `U1 开始 ～ U5 结束`，即 `2026-06-22 10:35 ～ 2026-07-03 09:40`。正确初始本体应为 `U2 开始 ～ U4 结束`，即 `2026-06-26 10:35 ～ 2026-07-01 11:20`。

## 3. 权威横向几何

### 3.1 初始本体

- 左边界固定为 `core_units[0].market_start`，即 U2 起点。
- 右边界固定为 `initial_exit_unit.market_start`，等价于 U4 终点/U5 起点。
- 纵向边界继续使用中间三段的固定交集 `[ZD, ZG]`。
- U1、U5 的价格和时间仍保留在审计角色字段中，但不扩张矩形。

### 3.2 后续延伸

只有完整回抽重新进入核心并被状态机接纳时，矩形右边界才延长到该回抽构件的 `market_end`。

若当前存在待确认离开段：

- 该离开段不属于矩形本体；
- 右边界停在该离开段的 `market_start`，也就是上一条已接纳回抽的结束时间。

因此统一计算规则为：

1. 左边界始终为首个核心段 U2 的 `market_start`。
2. 若存在 `completion_leave_unit`，右边界取其 `market_start`。
3. 否则若存在 `pending_leave_unit`，右边界取其 `market_start`。
4. 否则右边界取最后一个已接纳本体构件的 `market_end`。

### 3.3 第三类点与投影

- 不重新进入核心的回抽只负责原子产生第三类买卖点和 `COMPLETED` 状态，不延长矩形。
- 完成确认时间 `completed_at` 仍作为可交易证据时间，不作为矩形右边界。
- 进行中的 `center_projection` 从上述本体右边界开始延伸到当前已闭合 K 线。
- 已完成中枢不生成投影。

## 4. 实现边界

在 `TrendCenter` 上提供只读的核心渲染起止时间属性，使正式中枢、笔观察中枢和进行中投影共享同一权威计算，不允许各序列化路径再次根据 U1/U5 猜测边界。

既有 `body_start_market_time`、`last_touch_market_time` 保留其结构审计语义，不修改历史身份、结构 revision 或完成证据。`strict_chart.py` 只把图表 `points` 和投影起点改为新的核心渲染时间属性。

由于相同结构证据在新旧代码下会得到不同图形坐标，`render_revision` 的哈希命名空间从 `chanlun-chart-render/v4` 升为 `chanlun-chart-render/v5`；payload 的字段形状没有变化，`chanlun-chart-center/v4` 与 `chanlun-chart-structure/v4` schema 保持不变。这样已打开页面也会把几何变更识别为新的渲染代际。

图表缓存键已经包含 `core` 与 `cl_utils/strict_chart.py` 的源码指纹；相关源码变化后旧 `v40` 图表缓存自动失效，无需改变 payload schema 或手工删除缓存。

## 5. 测试设计

按 TDD 依次建立以下回归证据：

1. 初始五段中枢的矩形为 `U2.market_start ～ U4.market_end`，先证明当前实现错误地返回 U1/U5 时间。
2. 初始进行中中枢的投影从 U4 终点开始，而不是 U5 终点。
3. 回抽重新进入核心后，矩形右边界延长到该回抽构件结束时间。
4. 新的离开段出现后，矩形右边界停在离开段起点。
5. 第三类点完成后，矩形仍停在完成离开段起点，不延伸到回抽结束或 `completed_at`。
6. 价格点仍严格为 `[ZG, ZD]`，U1/U5 正宽重叠、状态机完成原子性和批量/增量稳定性测试继续通过。

Python 测试按精确测试名先运行 RED，再逐文件运行相关 `pytest`。完成后逐文件运行相关 Node 图形 reconciliation 测试，确保时间变化只更新目标矩形，不产生重复图形。

## 6. 真实运行验收

重启 `9900` 服务后，以 `SH.513100 / 5m` 验收：

- 最新正式中枢核心仍为 `2.200～2.214`；
- L0 完成中枢仍使用 5m 级别红色实线；
- 矩形时间改为 `2026-06-26 10:35 ～ 2026-07-01 11:20`；
- U1、U5 仍可由 payload 角色字段审计，但不在矩形时间内；
- 第三类卖点与完成状态保持一致；
- 当前快照不存在历史活动中枢的陈旧投影；
- 页面 K 线、成交量和 MACD 继续正常显示。

## 7. 非目标

- 不重新扫描或移动 `[ZD, ZG]`。
- 不改变五段成立门槛及 U1/U5 正宽重叠规则。
- 不改变第三类买卖点确认时间、买卖点价格或交易可见时间。
- 不改变递归级别颜色、显示菜单或走势类型。
- 不恢复任何旧三段中枢或原生高周期并行真值。
