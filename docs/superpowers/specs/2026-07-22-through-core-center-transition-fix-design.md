# 穿越核心区后的中枢换向修复设计

## 背景

`SH.513100 / 5m` 当前输出 9 个正式中枢，其中 5 个被标记为
`ongoing`。这 5 个中枢后面都已经存在锁定线段，因此它们不是仍在尾部推进的
活动中枢。真实逐段回放表明，它们都已经满足第三类买卖点，只是状态机丢失了
新的反向离开段。

当前状态机在存在 `pending_leave_unit` 时，只要下一段与核心区有正重叠，就调用
`_append_extension_return(..., pending_leave=None)`。当该段穿越整个核心区并从另一侧
离开时，它既是前一离开段的回归段，也是新的反向离开段；无条件清空
`pending_leave_unit` 会让紧随其后的有效三买或三卖无法完成中枢。

扫描器随后把无法继续推进的中枢仍以 `ongoing` 保存，并从冲突段继续寻找新中枢，
因此同一级别会积累多个历史 `ongoing`。序列化层会输出全部正式中枢，前端再把
`ongoing` 画成虚线，于是错误状态直接暴露在图表上。

## 已确认语义

1. 完成中枢仍只由第三类买卖点确认；不引入“时间到期完成”或“新中枢出现即完成”。
2. 第 1、5 段继续参与五段种子的正重叠校验。
3. 当待确认离开段之后的反向段与核心区正重叠时：
   - 若该段终点仍在核心区内，清空待确认离开段，中枢继续延伸；
   - 若该段穿过核心区并从另一侧离开，将该段登记为新的反向
     `pending_leave_unit`；
   - 下一反向段若停留在核心区外，则按新的离开方向确认三买或三卖并完成中枢。
4. 对连续、交替、已锁定的同级构成单元，每个结构级别最多存在一个
   `ongoing` 正式中枢；若存在，它必须位于该级别尾部，不能在其后已有未消费的
   锁定单元。
5. 不增加 `abandoned` 状态，也不在序列化或前端过滤历史虚线框。过滤会掩盖漏掉的
   第三类买卖点，并继续污染走势类型、递归级别和背驰计算。

## 状态迁移

保留既有 `advance_center()` 接口和 `TrendCenter` 数据模型，仅修正
“已有待确认离开段 + 新段与核心区正重叠”这一分支：

```text
pending_leave 存在
  ├─ 新段不与核心区正重叠
  │    ├─ 停留在原离开侧：确认第三类点，center -> completed
  │    └─ 其他非法几何：拒绝
  └─ 新段与核心区正重叠
       ├─ 终点位于核心区内：pending_leave -> None
       └─ 终点越过另一侧边界：pending_leave -> 新段
```

新段成为反向离开段时仍属于 `body_units`，并产生对应方向的
`BREAKOUT_WATCH_UP` 或 `BREAKOUT_WATCH_DOWN` 事件。后续第三类点完成时，现有
`core_body_end_market_time` 会以该离开段的 `market_start` 作为矩形右边界，因此
离开段不会被画入核心本体。

## 513100 验收基线

使用当前 QMT 复权缓存做只读回放，修正规则必须得到：

| 周期 | 当前结果 | 修正后目标 |
| --- | --- | --- |
| 1m | 8 个中枢：4 completed / 4 ongoing | 8 个中枢：7 completed / 1 ongoing |
| 5m | 9 个中枢：4 completed / 5 ongoing | 9 个中枢：9 completed / 0 ongoing |
| 30m | 2 个中枢：2 completed / 0 ongoing | 保持不变 |

5m 新增完成方向依次为 `up, up, down, up, down`，对应新增
`3buy, 3buy, 3sell, 3buy, 3sell`。正式中枢数量和价格核心不应改变。

## 测试设计

1. 先添加对称的 RED 测试：
   - 向上离开后，向下段穿越核心并从下方离开，必须把该向下段设为新的
     `pending_leave_unit`；
   - 向下离开后，向上段穿越核心并从上方离开，必须对称处理。
2. 紧随其后的外侧回试必须分别确认 `COMPLETED_DOWN` 和 `COMPLETED_UP`。
3. 改写当前把该几何称为 `abandoned ongoing center` 的扫描测试；相同输入应得到
   已完成中枢，不能继续固化错误语义。
4. 增加扫描结果不变量：同一级别最多一个 `ongoing`，且只能位于锁定尾部。
5. 逐文件运行中心状态机、模型、递归引擎、第三类点、增量前缀和图表序列化测试；
   前端协调测试必须保持通过。
6. 重启应用后从磁盘缓存和浏览器图形两条独立链路核对 513100 的
   1m/5m/30m 计数、第三类点、虚实线和矩形边界。

## 影响与缓存

该修复会有意改变中枢完成状态、第三类买卖点、走势类型、递归级别及其背驰结果。
不修改图表 schema；`center_machine.py` 已被源码指纹覆盖，代码变化会自动生成新的
缓存键并使旧的 QMT 图表计算缓存失效。

## 非目标

- 不改变五段种子和核心价格区间算法；
- 不改变第三类买卖点的边界包含规则；
- 不修改前端样式或用显示过滤掩盖状态；
- 不引入新的中枢生命周期枚举；
- 不处理与本状态迁移无关的工作区改动。
