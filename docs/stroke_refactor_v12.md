## 2. 原来的两个选择问题

旧选择器以一个当前起点组织所有输出。后段出现局部合格连接时，它可能因为旧范围内仍有价格候选而一直等待；另一种情形是更换起点后，旧范围整段从当前输出中消失。这两个动作都不能仅靠“起点还能参与价格比较”或“新路径存在”来证明符合全图划分。

本轮取消了“旧路径中任意端点仍在价格候选集合，就阻止后段观察”的条件。现在分别保存：

- 原始物理分型及全部局部关系；
- 各范围内当前选用的连接；
- 范围之间仍缺接法证明的边界；
- 端点选入、局部后继、当前连续前缀承接的不同证据。

范围边界是实现对未知状态的表达，**不是原文新增的一种笔，也不证明前后一定永远接不通**。前后范围不允许通过一次 `zip` 被连成虚构的边。

实现位置：[stroke_sequence.py](D:/project/chanlun-pro/src/chanlun/core/stroke_sequence.py)、[stroke_resolver.py](D:/project/chanlun-pro/src/chanlun/core/stroke_resolver.py)。

## 3. 当前取舍如何推进

1. 对包含处理后的K线识别完整物理分型。
2. 核验异类、独立K线距离和区间极值；过近分型的价格仍参加区间核验。
3. 排除从同一起点到同一终点具有完整反向分解的长连接。它是相邻性排除证据，不是全图唯一性证明。
4. 对经过当前取舍处理的候选核验同类极值、相等端点依赖、已舍弃内部分型和已保留反向结构；不是比较哪条路径的笔数更多。
5. 能在当前连续范围内接续或合法延伸时，更新该范围。
6. 后段已有局部合格连接、接回前段的依据尚不足时，保留前段并开立待接续候选范围。
7. 每个新分型到来时，重新核验早先待接续范围。若有合法连接，且保留了早先实际路径的前缀、没有绕过已保留反向结构，就解除对应边界。被替换候选的节点和选择事件仍可回查。
8. 实时尾部分型消失时，连同范围、边界、同价依赖和证据时间一起回退检查点。

第7步的前缀核验不能省略：两个候选即使继承同一个 `origin`，也可能经过完全不同的分型。复审中专门加入了防止“相同起点编号下的一条旧备选分支”绕过中间反向结构的检查。

对于用户限定的 `B>P、C<A` 初始结构，只有当前范围原先仅有 `P→A`、`A→B` 太近、`B→C` 自身满足旧笔条件时，执行受限的初始重选。这个数值分支是针对指定结构、结合第69课正文所作的程序推导，不是作者逐字列出的通用充要公式。

## 5. “完成”字段现在分别代表什么

| 字段／接口 | 当前含义 |
| --- | --- |
| `fractal_visible_at` | 尾端物理分型最早可见的来源时间 |
| `selected_at` | 此连接被选入当前取舍的时间；不能倒填成分型中心时间 |
| `continuation_at` / `has_qualified_successor()` | 所在候选范围内已经观察到合格后继；不证明前段接法已解决 |
| `component_index` | 当前候选所属的连续范围；不同编号之间不能视为相邻两笔 |
| `selection_pending` | 已识别的取舍或接续依赖尚未解决 |
| `locked_at` / `is_done()` | 兼容既有连续输入算法的承接标记；要求处于当前已知连续起始范围且没有相应待决依赖 |
| `completion_is_final` | 始终为 `None`：尚未提供原文意义上不可再修改的完成证明 |

因此，后段候选可以有局部后继，同时仍然 `selection_pending=True`、`locked_at=None`。接口不再把这两个事实混成一个“已完成”。

复审的50组生成数据中，仍记录到 **5次已标注承接的尾部连接因后续端点取舍而修订**，种子为21、30、31、35、47。它们被写入选择事件；重选会更新BI对象及依赖缓存，而不是偷偷沿用旧时间。这也是不能把当前 `is_done()` 解释成永久完成的直接证据。没有通过隐藏这些修订来宣称实现已经具备全局不可重绘性质。

实现位置：[line.py](D:/project/chanlun-pro/src/chanlun/core/types/line.py)、[bi_calculator.py](D:/project/chanlun-pro/src/chanlun/core/bi_calculator.py)。

## 6. 存量批量与实时增量

两类入口区别在状态管理，不是采用两套不同笔定义。

| 使用场景 | 入口及行为 |
| --- | --- |
| 完整存量快照、回放指定历史截止时刻、重做历史范围 | `CL.process_klines_batch(frame)` 建立新状态，成功后替换旧状态；包含、端点选择、确认登记和中枢缓存均不继承旧实例的结果 |
| 已完成包含处理的完整快照 | `BiCalculator.calculate_batch(cl_klines)` 明确重建 |
| 实时追加或尾根行情更新 | `process_klines` / `process_kline_values` 沿用处理器的增量状态；笔计算只在来源代次与前缀条件可信时走增量 |
| 旧尾分型被包含或改价撤销 | 回退最后一个分型的选择检查点；变化超出检查点能力则全量重建 |
| 来源没有可信代次／前缀认证 | 笔计算退回批量重建，不信任调用方列表身份 |

`CL_Kline_Process.process_cl_klines` 是有状态增量更新器，传入较短列表不代表删除旧历史。要把分析退到较早截止时刻，应使用完整批量入口；不能从最终划分中按端点日期截取来替代历史重放。

批量内部仍按分型顺序建立因果证据。这不表示系统要反复构建每一个原始K线前缀，也不表示最后快照可以把后面才发生的取舍提前确认。

`processing_mode` 只供诊断，未混入图表业务结果。相同行情快照的批量、逐根、分批和先历史后实时结果必须一致。

## 7. 下游与界面影响

`get_bis()` 返回全部当前候选连接，可能包括多个待接续范围。要求单一连续序列的调用改用 `get_contiguous_bis()`；`get_stroke_construction_state()` 返回边界中心、时间和原因。不能继续假设 `get_bis()[i].end == get_bis()[i+1].start` 对跨范围位置也成立。

线段和中枢当前只消费**已知连续的起始范围**。线段计算和单元适配器另外拒绝跨范围混合输入。未决边界后的候选笔仍显示为虚线，界面说明“笔的连接待定：线段和中枢仅计算已知连续范围”。关闭笔显示时，该提示仍由结构快照携带；它是分析待定，不是请求失败，不触发反复加载。

这有实际限制：后段候选很多，也不意味着该范围内所有线段、中枢、买卖点都已在主序列中恢复。本轮没有解决所有范围的全图接续，不能把后段没有确认输出解释成“原文认定那里没有线段或中枢”。

配置为 `old-source-sequence-v12`；CL缓存结构为 `chanlun-analysis-cl-v12`。旧版本对象不能冒用新字段语义。图表结构的待决标记也进入快照修订，避免同坐标状态改变不刷新。

涉及：[cl.py](D:/project/chanlun-pro/src/chanlun/core/cl.py)、[xd_calculator.py](D:/project/chanlun-pro/src/chanlun/core/xd_calculator.py)、[unit_adapter.py](D:/project/chanlun-pro/src/chanlun/core/strict_structure/unit_adapter.py)、[strict_chart.py](D:/project/chanlun-pro/src/chanlun/cl_utils/strict_chart.py)、[tv_chart.py](D:/project/chanlun-pro/src/chanlun/cl_utils/tv_chart.py)、[charts.js](D:/project/chanlun-pro/web/chanlun_chart/cl_app/static/js/charts.js)。
