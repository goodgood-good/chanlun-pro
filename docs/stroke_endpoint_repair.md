本轮把“单一端点栈 + 下一端点出现即完成”改为候选路径计算：每条输出边必须满足旧笔间隔和区间极值，未确认的端点可以重选，只有保留候选路径的共同前缀获得锁定时间。图表保留完整的待定笔尾部，线段继续计算候选几何，但依赖待定笔的结果不能获得正式确认。

**这是基于本地原文约束的一套保守工程实现，不是已经证明与原文唯一划分及完成时机完全等价的算法。** 四组样本的区间极值冲突已经消除，但确认可能明显延后：`SZ.002299 1m` 的 1,780 笔中只有 12 笔锁定。正式中枢和信号随之延后。不能把这种延迟称为原文的明确要求，也不能把“零极值冲突”当作完整符合原文的证明。

第 77 课第 217 行的“如果前面的底不低于后面的底”与上文条件存在理解上的歧义。本次没有自行改字，也没有据此声称证明了通用回退算法。

具体修复行为如下。

1. **成笔检查覆盖整个区间。** [BiCalculator](D:/project/chanlun-pro/src/chanlun/core/bi_calculator.py) 在距离、方向、价格检查后查询区间最大高价和最小低价。缺少完整区间证据时不放行，创建输出笔时再检查一次。独立的 [stroke_audit.py](D:/project/chanlun-pro/src/chanlun/core/stroke_audit.py) 继续从真实输出反查，避免测试只复述选择器内部的判断。
2. **不能立即成笔的分型仍可成为后续起点。** [StrokeCandidates](D:/project/chanlun-pro/src/chanlun/core/stroke_candidates.py) 为每个终点保存一条首选路径，并保留尚可能接续的终点候选。新分型严格突破旧同类候选自身极值后，旧候选不再可能直接连接更晚的异类端点，否则区间极值必然不符。相等极值不会按“突破”删除。
3. **路径排序是明确的工程选择。** 同一终点优先保留细分数较多的路径，细分数相同取较早前驱；展示端优先更深的路径，同深度优先维持已有选择。这是为了兼顾相邻分型取舍与显示稳定性。原文没有给出“最大细分数”优化问题，也没有证明这种排序对所有输入都等价于原文的相邻关系。这里的“候选”指本算法实际保留的候选，不能扩大解释为所有理论上可能的划分。
4. **端点选择与完成状态一起更新。** 只有新候选笔成立后，保留候选的共同前缀才可以推进；仅出现一个无法接笔的极端分型，不能单独确认旧笔。锁定时间取引起共同前缀推进的分型首次具备完整物理证据的时间，不倒填为笔端点日期。`confirmed_bis + pending_bis == bis`，`pending_bi` 兼容指向待定尾部最后一笔。
5. **允许多笔待定。** 共同前缀以外的路径可以重选。没有已确认笔时，旧候选全部失去接续可能后可以重新确定观察起点；已有确认前缀时不自动跨越它重选。如果所有接续候选耗尽，保留已有路径并暴露 `continuation_blocked_at`，不伪造一条不合格连接。这个边界是保守工程约定，并不宣称原文允许所有行情无限等待。
6. **增量缓存识别状态变化。** 末尾分型的中心或肩部证据变化时，恢复其计算前的检查点；更早变化则完整重算。完成状态变化也重建相应的笔对象，使线段计算的对象前缀缓存能看到它，避免几何未变时沿用旧完成状态。区间查询为 O(1)，追加区间表为 O(log K)；候选扫描开销仍取决于保留候选数，最坏情况没有承诺线性时间。
7. **下游保留候选结构，确认仍依赖已锁定笔。** 线段的第二特征序列继续检查当前待定笔路径；已有条件性几何边界不会只因为证据笔待定就被吞并成巨型尾段。`forming=False, locked_at=None` 表示候选几何已识别，仍未确认。缺口尚无所需分型时继续等待，不能绕过该条件。几何标准的本地依据是[第 67 课正文 64–118 行](<D:/缠论/chanlun_lesson_corpus/L067_线段的划分标准(2007-08-01223155).md:64>)及[第 71 课正文 100–124、172–208 行](<D:/缠论/chanlun_lesson_corpus/L071_线段划分标准的再分辨(2007-08-16230206).md:100>)；将候选几何与确认分开是软件状态设计。图表增加笔的种类标记，保留多条待定笔，正式中枢和信号的确认门槛继续生效。

测试使用 [test_stroke_endpoint_candidates.py](D:/project/chanlun-pro/tests/core/test_stroke_endpoint_candidates.py) 中完整 OHLC 输入，在每个前缀比较增量与完整重算，并断言以前确认的笔不能消失或改写端点、价格及锁定时间。“原始数据被用户修订”与“追加新的已收盘 K 线”不同：前者可以使历史证据失效，不能用不可回改承诺拒绝重算修订后的数据。

另有两个直接验证工程边界的场景。其一，展示路径保持 `1-5-9-13` 不变，但新的底分型淘汰替代起点，使 `1-5` 首次锁定；测试核验笔的锁定时间和线段缓存都刷新，不能只比较坐标。其二，`P-A、A-B` 合格后，过近的 `C<A` 和 `D>B` 耗尽接续候选，随后即使出现合格 `D-E`，本策略也不能擅自跨过已确认前缀重新起算。测试要求保留前缀并报告受阻时刻。**后一场景仍是此实现不能完整连续处理的边界，不应被测试通过掩盖。** 两组均覆盖上下镜像。
