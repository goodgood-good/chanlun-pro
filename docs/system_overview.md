# 当前系统功能说明

当前正式接盘图按显示的 K 线周期分别处理原始行情、笔、线段和本周期中枢。图表不再递归拼接走势类型，也不使用旧的走势类型、背驰和跨级别点位结果。多图布局、个人显示偏好、TradingView 指标和手动画线仍可保存。

保存图表布局时，将当前时间轴柱宽和左右偏移写入布局的原生timeScale字段；恢复有效保存视图后不再自动拉宽默认范围。相同标的、周期沿用保存的价格轴状态。选股图表默认读取相同账户的分屏和次要面板周期，并加载对应市场、面板保存的指标布局；主图定位当前候选及其周期。跨标的或周期复用布局时保留时间缩放及指标，价格轴重新适配数据。选股链接的临时分屏、周期不写回解盘页默认偏好。自选行情列表显示价格和涨跌幅，上涨红色、下跌绿色、零涨跌及缺失值为中性色，不显示接收时间。

左侧“画图”区域在“画线、画框”按钮上方提供“手绘周期”下拉框。1m图可选1m、5m、30m，5m图可选5m、30m，30m图可选30m；切换图表周期后默认选择当前周期。先选择所属周期再画图，颜色和新图形的周期归属使用该选项。例如在1m图选择30m后画框，该框按30m保存，能在1m、5m、30m中显示。改变选项不修改已经画出的图形。

周期选择过程中保持下拉框焦点，行情刷新不会重设正在操作的选项。失焦、点击控件外部、切换周期重建控件及销毁图表时，会撤销临时焦点保护并恢复原生工具栏行为。

手绘图形按所属周期分级显示：1m图显示1m、5m、30m绘图，5m图显示5m、30m绘图，30m图只显示30m绘图。这三种周期共用完整的手绘保存状态，由图表库控制可见性；隐藏的图形仍被保存。在低周期编辑高周期图形不会改变其所属周期，删除当前可见图形也不会删除其他隐藏图形。周期之间切换无需重载同一份手绘状态，因此尚未发出的保存不会被旧缓存覆盖。

保存请求在排队前记录原标的、周期和明确的手绘身份，不使用切换后的图表身份写回；同一保存位置的请求合并为最新状态，不同保存位置的请求分别保留。自动结构在异步确认身份后也会从待保存快照中排除。旧共享或独立周期记录首次读取时按已有创建周期合并，保留原记录；缺少创建周期的旧共享图形维持共享可见性。新的保存记录优先，删除全部绘图后不会重新导入旧副本。账户、布局和图表位置的存储隔离沿用现有边界。

## 买卖点提醒

一、二、三类买卖点是用户指定的本周期程序规则，并在界面显示为已确认的正式提醒；这一身份不等于已经完成全部缠论走势类型的原文认证。

当前采用的操作口径是：每个 K 线周期以该周期已经确认、首尾相接的线段作为分析次级成员。快照的 `native_member_policy` 记录来源周期、线段成员口径及完整递归类型尚未证明的边界。第57课第79—103行给出按最小分析级别观察线段的方法；第65课第622—643行区分这种操作性处理与严格递归意义。原文出处分别为 `D:/缠论/chanlun_lesson_corpus/L057_当下图解分析再示范(2007-05-31223544).md`、`D:/缠论/chanlun_lesson_corpus/L065_再说说分型、笔、线段(2007-07-16221416).md`。采用本周期线段作为成员是当前用户选择的程序规则。

| 类型 | 本周期程序判定 |
| --- | --- |
| 一类 | 至少两个前后严格分离的本周期中枢构成同向背景；后一中枢完成离开及首次回试后，完整三线段离开腿创出该方向的新价格极值，且相对后一中枢的实际进入腿，MACD 同向柱面积缩小。 |
| 二类 | 从一类点真实价格极值所在段起，检查紧接的反向线段及首次同向回试；均须已锁定、首尾相接，且回试不越过一类点极值。首次回试可以位于完整一类比较组合内部，二类点的可知与确认时刻不得早于其父一类点可被识别的时刻。 |
| 三类 | 已成立中枢独立离开后，紧接的第一次反向返回线段保持在中枢核心相应一侧。 |

信号使用线段和中枢的来源 ID、真实价格极值、确认时间以及价格基准生成稳定身份。筛选发布前，程序会独立重算完整输入，并在信号首次可知的 K 线前缀重放，防止使用后来的数据回填。价格越过失效边界、同周期后续反向点已经确认，或点位结构锚定段紧接的反向线段已确认完成时，旧信号退出当前提醒窗口。一类点对应的二类点已有有效确认时，一类点也退出当前候选；二类点后来退出不恢复父一类点。后继线段尚在形成时不作为完成依据；历史图表标记保持其原有确认身份。

反向点的价格拐点和可知时刻均须晚于原点，避免将早已可知的内部反向点倒写成后续结束条件。原文第45课第37—49行讨论操作级别的后续卖点和持股、持币转换，出处为 `D:/缠论/chanlun_lesson_corpus/L045_持股与持币,两种最基本的操作。(2007-04-12.md`；这里按用户采用的本周期分析口径管理提醒窗口，是程序策略推导，并未重新定义历史买卖点。

筛选涨跌幅以快照的价格精度将最新收盘价对齐到整数 tick，再用十进制计算比例；恰好达到所设上限仍保留，超过上限一个实际价格 tick 时按条件排除。冻结结果校验同时检查整个中枢的进入、核心、延伸、离返来源、价格交集及时间链。单条行情记录的全部候选验证通过后才发布，结束提醒的原因保留在筛选诊断中。

## 周期和通知

筛选可同时选择 1m、5m、30m。每个周期只计算自己的中枢和点位，不把图上的 30m K 线等同于递归结构级别。监听按所选周期中最短的收盘时钟触发，逐周期读取各自的行情截止时刻。通知沿用用户原有的启用状态与去重设置。

各市场分别按实际观察时刻建立所选周期的行情上下文；非 A 股的 1m 和 30m 不再从 5m 截止时刻派生。运行记录保存各市场、各周期实际行情截止，页面时效判断和日期说明使用这些市场时钟。算法版本过期时，现有监听池会在同一收盘时钟下重查一次。单个周期的数据异常仅阻止该周期作出提醒结束判断，其他成功周期仍可独立更新。

页面时效按市场和周期分别核对。某市场缺少截止记录或日历不可用时，不阻止其他市场显示核对结果；运行中的缺失记录显示等待，任务结束后仍缺失则显示无法核对。已知市场有更新收盘K线时，整轮标记包含过期数据；部分市场无法核对时不将整轮标记为最新。单条候选按自身市场、周期的结果显示时效，其他市场的问题不把正常的A股候选一并标成待更新。

选股页不再显示顶部大段时效、历史排除说明，相关记录保留在折叠的运行与数据诊断中。自选分组加载后立即请求报价，不等待选股结果读取和校验。各市场独立管理在途请求及下次刷新时间；慢市场不阻塞其他市场，接口要求稍后重试或退避时按返回的时间继续。当前分组或可见候选改变后，成功完成的旧请求会衔接新名单；同一市场不重叠发起请求。

行情适配器初始化也按市场隔离，同一市场保持单例，慢市场的连接不占住其他市场的初始化锁。外汇初始化最多两次连接尝试，每次连接超时5秒，关闭SDK叠加自动重试；失败会交给调用方退避，恢复后可以重新创建实例。外汇前收盘基准缺失时涨跌幅为未知，不伪装成0%；没有已核实交易时段时，不声称始终开市。

已经明确缺少结构计算时间口径的行情适配器，会在请求大批历史K线前返回对应诊断。缺少分钟时间标签和交易日历分别保留为独立原因，不混同于中枢或买卖点引擎计算失败；正常图表、报价和有完整时间依据的数据源沿用各自接口。

监听和结果时效核对按交易日历、观察分钟及周期复用收盘时钟。缓存容量有上限，完整上下文对每个标的返回独立列表；进入下一分钟重新核对，未完成 K 线不会进入截止时刻。A 股日历无法核实时，A 股定时选股保留诊断，其他已有有效日历的市场继续监听。

A股选股和监听的历史起点也按该周期已收盘截止日期计算，沿用行情适配器配置的回看长度；跨午夜、周末或假期而没有新收盘K线时，不截掉旧历史改变结构结果。更长的交易日回看要求和缺口修复仍可将起点向前扩展。

QMT股票分钟线、日线还核对独立提供的上市日期。上市前的零成交占位记录会被排除，并保存所用日期和移除数量；不会把这段日期间隔当作上市后的行情缺口。特殊日期值、缺少元数据以及指数和基金不会按此规则截断。若上市前存在非零成交，保留原始记录并报告上市信息冲突，选股和图表结构均不据此生成信号。完整的上市后本地行情可以直接复用，避免重复下载不可能存在的上市前交易数据。

临时行情或计算错误会在同一截止时刻有限重试。一轮最多检查三次；默认间隔为首次失败后 60 秒、再次失败后 120 秒，用户设置更长检查间隔时相应延长。达到上限后保留异常诊断，等待新收盘 K 线、用户立即检查或新算法版本。重试状态随监听状态保存，重启可以继续；尚未检查的标的先于失败重试进入批次。

监听每批最多64个标的，工作进程仍按既有并发上限运行。还有待查标的时，上一批已完成且结果消费结束后，下一次调度即可继续下一批，不额外等待整段检查间隔；没有待查队列时恢复原检查间隔，失败标的仍遵守重试退避。此方式减少股票池大于单批上限时的空等时间。

每批实际进程数同时受标的数量限制，单标的使用1个进程，两个标的使用2个进程。已落盘结果按每次16个标的读取；若还有已经完成的结果，立即唤醒下一轮读取，不再额外等待3秒。监听批次仅走逐批证据读取，不再启动一个无页面使用的整批结果预热线程；全量选股仍保留页面结果预热。

全量选股运行期间，原监听池与当前持仓继续检查，每批最多16个标的、最多2个计算进程，持仓和关注标的优先。全量任务完成后才替换选股来源名单，再恢复常规监听批量；部分选股结果不会提前成为新监听池。同一时刻仍只运行一个监听任务。

数据失败期间，相关信号不作为当前正式提醒显示，也不立即记录退出。程序只在内部保存其身份用于后续核验：成功恢复后，仍有效的相同点位恢复显示而不重复发现；已经退出的点位在成功检查时记录退出。选股页面保留此前成功检查的退出证据，失败不会让已移除候选重新出现；其他受影响候选暂不显示，并在诊断中报告待恢复数量。首次检查失败、工作进程中断和交易日历异常都采用此处理。行情截止早于上次成功检查时按失败处理，旧结果不能覆盖较新的信号状态。日历恢复后即使收盘时刻未变也补查，超过单批上限的标的继续排队。

每个被检查周期都必须有对应的成功证书，其他周期成功不能代替。变更监听周期或类型后清理范围外记录。持仓分组暂时不可读时，持仓盘整背驰进入待核验状态，恢复后按原截止补查；不把读取失败当作持仓已经清空。通知排队重试时，再核对当前信号、实际持仓及最新周期检查；已经失效的消息撤销，暂时无法核验的成员等待，已核验成员独立发送。

通知队列按下一次可尝试时间排序，再按创建时间排序。等待复核的旧批次退到新的重试时刻，不会依靠较早的创建时间反复抢在已就绪消息前面；发送间隔、过期处理、证据复核和持久化去重仍各自生效。

工作进程中断后，已消费且版本仍有效的结果保持，尚未消费的标的安排补查；代码版本已变的工作结果不继续作为当前信号显示。版本重查以目标源码版本去重，避免没有源码标识的失败批次不断触发全池重算。

监听页面读取时也按当前算法版本过滤整个信号池，每个标的周期必须有对应版本的复核记录，才进入当前列表。这项检查在调度器运行之前、重启之后和跨批次重算期间都生效；仅隐藏待重新核验的显示，不删除历史、不记录假退出，也不改变去重身份。全量选股与实时监听同时运行时，页面展示实际监听进度，不再显示等待选股完成。

源码更新后，已完成的本周期中枢批次仍可按原行情截止复核。页面只展示通过当前来源和证据检查、规则标识一致的冻结点位，并明确显示历史结果状态。通过当前独立复核的历史本周期批次可提供监听的待检查股票名单，历史点位不得直接成为当前通知；监听以当前版本和新行情重新计算。工作台按同一批次、同一读取版本的成功周期检查移除已退出候选，旧于保存行情截止的检查及失败检查不作为退出依据。历史复核继续保留源码过期标识，结果缓存和页面轮询同时感知当前源码与读取端版本。

选股工作台请求轻量的完整候选索引，每页显示50条，搜索和筛选覆盖整个索引；完整证据在选中候选时单独加载，导出时再读取完整详情。页面按复核内容版本更新，覆盖同一秒内完成的多次检查；单条详情缓存按自身周期的复核版本失效，无关股票更新不重复下载该详情。响应的证据版本、读取版本及复核版本必须与当前列表一致。切换股票时先清空旧证据并切换图表地址，迟到的详情不得覆盖新选择，报价优先刷新当前页。已完成的独立证据校验结果自动保存为原子缓存，重启可复用；源码、读取规则或证据文件变更使缓存失效，新证据仍须完成独立校验。

实时监听页面的当前信号、完整监听名单和监听历史在后端独立分页，默认每页50条，可选择25或100条。搜索覆盖对应列表的全部记录，页头数量仍为全量统计；历史范围沿用最近500条。页面只接收当前页的展示字段，不传输完整证据、检查字典及重复股票名单。自动刷新保留搜索、每页数量和页码，数据减少时将页码收回到有效范围；请求15秒超时后可以继续轮询，搜索和翻页取消旧请求。后台仍监听完整名单并按原规则通知。名单区分别显示检查通过、数据受限和待核验数量。从监听页面打开图表会加载同账户保存的指标布局。

选股页的自选区域显示当前分组名称、该组总标的数和各市场数量，使用中文市场名称。切换分组时清除上一组内容并显示读取状态，迟到响应不覆盖新选择；失败与空分组分别提示，同组刷新失败时明确标记上次成功读取的数量。分组读取状态与行情刷新状态分别显示，数量不与选股候选数混用。

选股进行中会展示已完成并通过证据校验的候选。后台按已提交记录连续校验，每批最多64个标的，不足64个也可开始；每批完成即发布，页面每5秒轮询更新，并分别显示已处理和已核验数量。新增记录不会清空已校验列表，也不会重复校验整个前缀。已核验记录的原始字节及所用证据文件仍须保持一致；已有记录或证据变更、提交进度回退、版本变化或新任务替换时，旧缓存失效。完成后转入原有结果缓存；取消或中断仍可查看已经完成校验的部分。单条详情版本独立于整轮追加记录，新增其他股票不会清除所选候选或复核草稿。

“我的持仓”分组是人工维护的持仓来源。组内标的继续接收已有买卖点通知，并增加独立的向上、向下盘整背驰通知；其他关注标的不增加该通知。持仓即使没有选股入选结果也会进入监听池，加入持仓时安排补查，移出后停止新盘整背驰提醒。

已确认盘整背驰沿用本周期已确认线段成员口径，比较一个已确认中枢的同宽进入、离开腿，或中枢内由反向段连接的两段同向摆动。来源必须完整、锁定且首尾相接，C 段原生 MACD 同向柱面积小于 A 段；中枢内比较不附加突破中枢或创新价格极值条件。失败离开及回归也纳入该中枢的摆动比较，但三段都必须与核心重叠。比较腿确认后，还须通过独立重算、首次可知时刻及前一根 K 线的回放边界核验，才发布已确认通知。
