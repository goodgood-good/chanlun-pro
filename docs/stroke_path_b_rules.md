# 旧笔构建工作规则：纳入用户对三组图的判定

更新日期：2026-09-15。当前生产版本为 `old-user-path-b-completed-prefix-v14`。本文区分本地原文、用户判定与工程推导；本轮修改已经接入生产计算器，旧独立模型只保留为历史研究材料。

## 已经确定的范围

- 只研究旧笔，不使用新笔规则。
- 使用正常行情，排除9:25竞价，不补造K线。
- 不采用特殊缺口成笔规则。
- 初始化从最早已有行情中寻找相对高低点，不要求全历史极值。
- 两端分型之间至少有1根独立K线，处理后中心索引差至少4。用户已经针对“间隔大于1”的表述明确选择沿用这一标准。
- 原争议样例仍采用路径乙 `T0→B2→T4→B3`。

包含处理、标准顶底分型仍按此前核对的基础定义处理。[第62课，第37—118行](<D:/缠论/chanlun_lesson_corpus/L062_分型、笔与线段(2007-06-30094951).md:37>) 独立中间K线与顶底区间关系见[第77课，第121—148行](<D:/缠论/chanlun_lesson_corpus/L077_一些概念的再分辨(2007-09-05232401).md:121>)。

第三项根据用户“C出现符合规则的笔、出现顶分型”的表达，整理为从C出发的下一条笔C—D。顶D需形成标准分型、与C间距合格，并满足顶底价格关系。价格关系沿用第77课顶中心区间至少部分高于底中心区间的表述，不将笔定义简化成只比顶价与底价两个数。

向下笔完成采用对称推导：`A顶→B底→C顶→D底`中，C—D合格后确认A—B。对称表达是本轮推导，不是用户的逐字原话。

当前局部价格资格采用对称的形式化：顶中心K线的高点、低点分别严格高于底中心K线的高点、低点。等于或包含的边界不放行。这是对区间文字及上下对称性的工程解释，不是作者给出的布尔公式；反转全部价格时必须得到对称结果。

## 初始化与第一次成笔

1. 最早可识别的标准相对分型作为初始候选，不寻找全历史最高最低。
2. 尚未有首笔时，保留短间隔反向候选中更极端者；同价保留较早者。后来较弱、恰好够距离的同类分型不能直接覆盖它。若该反向候选能与后来的分型构成首笔，从这个相对起点开始。
3. 仅有一条未完成首笔 `P—A` 时，核对第69课初始四分型关系：A与后来的B太近，B比P更极端，C比A更极端，B—C合格，则改选B—C。此项是将图文关系转成事件条件，限定在最初两个入选端点；不能扩大成任意恢复历史候选。

同类分型的严格极值与同价先保留见[第77课，第247—283行](<D:/缠论/chanlun_lesson_corpus/L077_一些概念的再分辨(2007-09-05232401).md:247>)。初始四分型的取舍见[第69课，第28—49行](<D:/缠论/chanlun_lesson_corpus/L069_月线分段与上海大走势分析、预判(2007-08-09.md:28>)；其第52行起的“注”没有作为作者正文使用。

## 端点取舍与完成状态怎样配合

针对本次样例，可以整理出以下事件顺序：

1. 按时间顺序处理分型及其入选状态，原始行情和已识别形态保留。
2. 路径乙短冲突发生时，在尚可修改的尾部按当前选中链重选；本次图1删除A、B的入选身份，图2最终删除B2、T4的入选身份。
3. 已舍分型后来能与某点满足局部连接条件，不自动触发历史恢复。图2明确选择T0—E，不能再用“完整候选搜索能画更多笔”推翻该选择。
4. 当前形成A—B—C—D，且C—D成为合格笔时，产生A—B的完成确认记录；不能仅按物理分型数量计数。
5. 完成记录保存当时的A、B、C、D、物理见证时间及实际确认时刻。此后普通行情追加可重新取舍右侧的B—C、C—D，已经确认完成的A—B及其历史承接证据保持不变。
6. 历史行情修订或包含表示被重建，应按数据修订重新计算；不能与普通追加下任意撤销已完成笔混为一谈。

第5项由用户给出的确认时机与原文“完成后不再修改”共同推导。[第69课，第151—166行](<D:/缠论/chanlun_lesson_corpus/L069_月线分段与上海大走势分析、预判(2007-08-09.md:151>) 原文没有规定本项目的事件、字段或事务名称。

图2的选择仅足以否定“本例应恢复B1、T2”。它不能单独证明在所有行情修订和不同结构中，所有未入选候选都永远不能重新参与。因此，不永久删除原始数据或形态证据。

一般尾部按以下顺序处理：同类严格更极端且能连接左端时替换尾端；异类局部合格时追加；异类太近、比倒数第二端更极端且能接倒数第三端时，删除末两个入选端点并重接。其余只保留物理观察。同价不通过寻找较早父路径改变已选链。

任何替换或重接都必须先检查完成前缀，再修改选中链。如果连续短冲突需要删除某个已完成端点，拒绝这次重接，保留当前连续笔链与新分型，等待后续合格分型。该规则修复了旧独立模型先改写、再断言失败的问题；不另外制造一个断开的笔分量，也不虚构连接。

## 完成时机的具体对照

图3三种情况分别为C高于A、等于A、低于A。截至索引10都只有A—B—C，尚未触发本次完成规则。

- 若新顶D在中心12，C在中心9，中心差3：C—D不成笔，不触发A—B完成。
- 若新顶D在中心13，于索引14形成标准顶分型，C—D中心差4且价格关系合格：三种情况均在本模型的索引14触发A—B完成。
- 后来出现太近且更低的E，右侧可由B—C—D重选为B—E，完成的A—B保留。

同理，图1在内部B（中心13）确认时，S—P—A—B已有第三条合格连接A—B，故S—P已确认。后续短冲突改接P—C时，保留S—P。图2则在两次短冲突前均没有形成触发最早一笔完成的第三条合格连接，因此可以依次收缩到T0—E。

这些说明对应固定合成行情和本次工作判据；代码对任意输入采用相同顺序事件规则，但有限测试不等于证明任意输入都只有这一种原文划分。

## 批量与实时处理

同一行情快照、同一左侧条件、规则版本与收盘事件口径，批量顺序处理与逐根增量重放应得到相同的当前选择和完成记录。批量处理不能重新枚举历史候选并以笔数更多为目标，推翻已选定的事件取舍方式。

未收盘K线变化、追加新K线、历史数据修订分别处理；同一确认事件不能重复产生完成记录。上述是软件一致性要求，不冒称原文直接规定了程序结构。

| 入口 | 默认收盘口径 | 用途 |
|---|---|---|
| `CL.process_klines_batch(frame)` | `last_bar_closed=True`，全部输入已收盘 | 存量历史一次性重建；清除该实例旧计算状态 |
| `CL.process_klines(frame)` | `last_bar_closed=False`，末根仍在形成 | 全量快照、重叠行情和实时增量；自动识别历史修订 |
| `CL.process_kline_values(...)` | `bar_closed=False` | 单根实时快速入口；可以显式传 `bar_closed=True` |
| `CL.process_validated_incremental_klines(frame)` | `last_bar_closed=False` | 已由调用方核对历史前缀的可信快速入口 |
| `BiCalculator.calculate/calculate_batch` | `closed_through='all'` | 直接输入包含后K线的底层入口；默认全部已收盘 |

若历史加载帧包含正在形成的末根，批量入口必须传 `last_bar_closed=False`。同根行情变化可以撤销尚未收盘的分型，不能提前产生不可撤销的完成记录。价格没变、只收到显式收盘信号时，也需要推进完成判断。

`physical_witness_at`记录物理见证K线时间；`locked_at/witnessed_at`记录按输入约定实际获知完成的时间。默认实时入口在下一根到来时知道上一根收盘，因此实际确认时间可能比物理见证晚一根。若调用方明确送入收盘事件，则按该事件的K线时间确认。K线标签是事件时间约定，不推算交易所墙上时钟的收盘秒数。

先批量加载已收盘历史、再接盘中行情，属于混合收盘事件序列，保存两阶段各自的确认时间。仅用最终OHLC做另一次统一口径的批量重放，可能有不同的确认时间；要复现所有时间证据，还需保留相同的收盘事件历史。相同口径的批量与增量已分别验证。

已经收盘的历史价格修订会重建K线、MACD、包含、笔及下游依赖。这是新的行情修订状态，不属于普通追加中撤销完成笔。缺失旧行不视为删除；需要替换观察窗口时使用批量入口。旧版本对象由规则版本和 `chanlun-analysis-cl-v14` 序列化版本拒绝复用。
