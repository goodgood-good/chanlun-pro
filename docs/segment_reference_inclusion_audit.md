# 前侧参考的包含贡献与顶点资格

日期：2026-09-16。依据限于实际读取的 `D:\缠论` 原文及配图。以下数值案例、程序性质及其推广均为本次推导，不是原图行情。

## 已修正的问题

前侧参考更新曾先检查某笔是否创新高／新低，再检查包含。这样会把两个不同问题混在一起：一笔不构成新的参考顶／底，仍可能参与已有标准元素的包含，改变其另一侧边界并提供来源。

这一遗漏发生在生产计算器 `_advance_left_reference` 中。现已改为先保留当前参考元素内的包含贡献，再对不包含的元素判断是否具有新参考顶／底的资格。原始笔仍全部保留；没有把包含后的区间替换成一根物理笔。

## 可复现的两个例子

点、笔从零编号；笔 i 连接 Pi 与 P(i+1)。强首笔的例子为：

```
0,10,6,14,4,12,8,15,9,13,7
```

P3=14 之后，笔 3 `[4,14]` 与笔 5 `[8,12]` 同侧包含，向上处理得到 `[8,14]`。随后 P7=15 严格创新高，旧候选取消，原段继续。此时前侧参考按时间处理笔 1、3、5：

| 步骤 | 标准区间 | 来源 |
|---|---|---|
| 初始笔 1 | `[6,10]` | 1 |
| 加入笔 3，向上包含 | `[6,14]` | 1、3 |
| 加入笔 5，继续包含 | `[8,14]` | 1、3、5 |

旧实现因笔 5 的高点 12 没有超过 14，停在第二步，保存 `[6,14]` 和 `(1,3)`。修正后保留 `[8,14]` 和 `(1,3,5)`，低边由笔 5 提供，高边仍来自笔 3。这里既没有新增参考高点，也不能丢弃低边的改变。

另一例 `0,10,6,14,8,12,9,15,11,13,10` 中，笔 1 与笔 3 不包含；随后笔 3、5 包含。旧参考 `[8,14]`、来源 `(3,)`，应改为 `[9,14]`、来源 `(3,5)`。两例都仍在 P10 确认 0—7，随后 7—10 形成中。问题是保存的标准参考区间和来源不完整，不能将它描述为这两例的段界错误。

## 为什么本次不应改变段界与确认时间

这里证明的是此次代码变换对现有有效输入的影响，不是全部参考资格已经符合原文的证明。

向上时，修改前后参考高边都等于已扫描参考候选高边的最大值：不创新高的包含不改变它；创新高时，两种写法都更新到新高。修改后可能抬高低边、补充来源。向下镜像中，低边仍为同一最小值，变化的是另一侧高边及来源。

普通向上分型的严格极值检查只比较中间高点与左、右高点。对一个已成立的顶分型，中间高边大于左高边，故前两个标准元素有缺口当且仅当 `中间低边 > 左高边`，与左元素低边无关。向下时对应 `中间高边 < 左低边`。所以这次参考另一侧边界的修正，不改变分型成立或第一／第二种的分类。

提前排除普通候选的条件也只使用这一方向极值；局部强首笔分支独立从原始笔及 `pivot_stem` 取参考；第二序列仍从相同候选的原始笔重建。因此，在当前代码路径上，后续扫描位置、实际端点和见证位置保持一致。确认时间本来就检查从段首到见证的全部原始笔，并不只检查参考元素列出的笔，所以补齐参考来源也不会额外改变确认时刻。

这一控制流与区间推导另用受控对照验证：在当前代码中仅恢复“先筛选后包含”的旧函数，比较段界、状态、确认时间、实际价格范围、父子关系、见证以及除前侧参考以外的全部证据字段。没有借用另一套笔算法，也没有将两个不同历史版本的全部差异混合比较。
